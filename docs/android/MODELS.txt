EchoLite local model management — active development

Both native interfaces expose Unload models / Load models in the navigation
sidebar (open the menu on Android). Unload stops generation and embedding workers,
retains downloaded files, conversations, Me, memories and durable caches, and
persists the unloaded preference. Reopening does not load models until requested.
The app prevents a button-triggered unload during its active operations; the
runtime also takes the inference-slot lease and checks that both listeners close.

The default is Qwen3.5-4B on both devices. The sidebar Next: 4B / Next: 9B button toggles a persistent device-local preference for the next load. Selecting a preference does not unload or restart a running model. Use Unload models, then Load models to apply it. Selection runs before starting a generation engine. A verified resident engine is
reused to avoid switching during an ongoing conversation. Loading after an unload
re-evaluates memory. The installed profiles retain the 262144-token native context:
- Qwen3.5-4B Q4_K_M with its Q8 vision projector: established 8 GB desktop profile.
- Qwen3.5-9B Q6_K with its matching F16 vision projector: larger Android profile.

The larger profile is opt-in and requires at least 20 GiB physical RAM, at least 16 GiB currently
available RAM, and complete weight AND projector files. The admission allowance
covers weights, full-context KV, vision and working space. Swap/RAM expansion is
not counted as physical RAM. Missing assets, unknown capacity or memory pressure
select the smaller installed profile. A failed larger-model startup falls back to
4B. These are two supported profiles, not a claim to rank every available model.
The current Mac admission policy retains its measured 4B profile.

Android profiles retain four recurrent-context checkpoints (about 201 MiB in the
measured 4B run), allowing chained rounds to reuse earlier prompt boundaries.
The 8 GB Mac 4B profile retains its single checkpoint.

The active model is displayed in the chat header. Response, tokenizer and native
slot caches are bound to model identity. The existing 4B namespaces remain intact;
9B uses a separate namespace. The startup manager records the verified selection
next to the shared runtime credential; exact cache replay needs no model HTTP call.
