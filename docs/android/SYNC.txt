Automatic synchronization update — 2026-11-19

The paired Mac and Android installations now run a native Ernos Plain sync agent.
The UI starts it automatically and checks its process every five seconds. This
Mac also runs it through a per-user LaunchAgent so closing its window does not
stop synchronization. Android now owns the worker through an EP-generated foreground service in a
separate process, with boot and package-update receivers. See BACKGROUND.txt
for lifecycle, device settings and explicit user-stop behavior.

The Mac refreshes its authorized ADB forward every three seconds and initiates
bidirectional USB exchanges. Android initiates Wi-Fi exchanges after USB receipt
has been quiet for fifteen seconds, using saved endpoints and authenticated LAN
discovery. Active chat workers defer maintenance; finalized records transfer in
bounded batches. The agent does not load an additional language model.

Pairing keys remain private in each local database. Mac USB configuration lives
in data/sync-usb.json with adb (absolute executable path) and serial fields.
Those machine-specific values, keys, and databases must not be committed.
For an already paired installation, normal builds now include echolite-sync;
Android APK builds include libecholite-sync.so. The UI starts the worker itself.
The optional Mac login service must set ECHOLITE_HOME and invoke bin/echolite-sync.

Open conversations on different devices no longer block history imports. An
incoming open session is stored as history when a different local session is
active, preserving the local conversation selection. This does not turn two
independent active conversations into one shared live generation.

- With USB forwarding paused, Android completed an automatic Wi-Fi transfer.

- Concurrent-open-session regression passes; 21 coordinator checks pass.

Scope: session history, finalized turns, memories, tasks, Me revisions, and tool
